## 2. 差距模块拆解（按主线重要性排序）

### 主线 P0 —— 标杆缺失（面试叙事的骨架）

#### M1. GTM 产品营销标杆 ❌
- **现状**：GTM 域只有"客服培训"小系统，没有能代表"GTM 产品营销 Agent"的标杆
- **候选**：达人自动筛选建联（需求方点名，2-3 天，GTM 域唯一被点名）
- **为什么是它**：需求方亲自点名 + 工程量适中 + 覆盖"数据接入→AI 打分→话术生成→流程跟踪"完整链条，能证明 GTM 域交付能力
- **面试叙事价值**："GTM 域我交付了达人建联 Agent——从名单导入、粉丝画像打分、个性化话术到寄样跟踪全流程"

#### M2. IPD 项目管理标杆 ❌
- **现状**：IPD 域零交付
- **候选**：会议→行动项→自动看板（需求方点名，2-3 天）
- **为什么是它**：需求方点名 + "自动对账"是 IPD 域最有技术含量的环节（看板状态回写），能证明 IPD 域交付能力
- **面试叙事价值**："IPD 域我交付了会议看板 Agent——会议转写抽取行动项、自动建任务、下次开会自动对账"

#### M3. 第三个作品厚度 ⚠️
- **现状**：只有 2 个可演示作品
- **解法**：M1 + M2 落地后自然解决（4 个作品：招聘/售后助理/达人建联/会议看板）

### 主线 P1 —— 已交付系统的生产级差距（从"能跑"到"像企业用的"）

#### M4. support-assistant 生产级差距
当前是"可用的 RAG 问答"，但企业实际客服培训系统还差：

| 子模块 | 差距 | 严重度 | 面试价值 |
|---|---|---|---|
| M4.1 知识库管理界面 | 语料是静态 jsonl，无上传/编辑/版本管理界面 | 中 | 证明"业务专家能自助维护知识库"（手册承诺的能力） |
| M4.2 演练打分模式 | 只有问答，无"AI 扮演难缠客户 + 客服应答打分"的培训闭环 | **高** | 这才是"培训系统"区别于"知识库问答"的核心 |
| M4.3 测验模块 | 无自动出题/判分 | 中 | 培训效果量化 |
| M4.4 使用分析 | 无"客服常问问题排行 / 知识盲区"统计 | 低 | 管理价值 |

**判断**：M4.2（演练打分）是主线——它把售后助理从"知识库工具"升级为"培训系统"，正中需求方点名的"产品客服**培训**系统"。M4.1/M4.3/M4.4 是使用感提升。

#### M5. resume-screening 生产级差距
| 子模块 | 差距 | 严重度 |
|---|---|---|
| M5.1 批量上传 | 当前单份处理，企业是批量简历 | 中 |
| M5.2 看板视图 | 结果列表，无"待审/已通过/已拒绝"看板流转 | 中 |
| M5.3 HR 确认动作落库 | "人做最终决定"是红线，但确认动作没有持久化记录 | **高** |

### 主线 P2 —— 工程化手册的可复现性（需求方要求 4 的深化）

#### M6. 手册实战验证
- **现状**：手册写好了，但没有"业务专家按手册做出一个简单 Agent"的实证
- **差距**：缺一个"手册复现案例"——用 template 快速做一个新系统（如入职引导 Bot，清单里标注"RAG 脚手架直接复用，1 天"），证明手册真能让业务专家自助
- **面试价值**：直接回应需求方要求 4，且成本最低（1 天）

## 3. 推荐执行顺序（主线优先，控制单批工作量）

**第一波（P0 标杆补全，面试叙事骨架）**：
1. **M1 达人自动筛选建联**（2-3 天）—— GTM 标杆，需求方点名
2. **M2 会议→行动项→看板**（2-3 天）—— IPD 标杆，需求方点名

**第二波（P1 生产级深化，选做）**：
3. **M4.2 售后助理演练打分模式**—— 把"客服培训"做实名
4. **M5.3 简历初筛 HR 确认落库**—— 红线动作持久化

**第三波（P2 + 使用感）**：
5. **M6 手册复现案例**（入职引导 Bot，1 天）—— 证明手册可复现
6. U1-U5 按需

**每波交付后**：更新 demo 视频 + RECORDS 台账 + 面试叙事稿。

## 4. 面试叙事定位（差距分析的最终目的）

完成第一波后，你的面试叙事是：

> "我为消费电子企业设计并交付了 VibeCoding Agent 方案库：三大业务域标杆各一个——招聘（简历初筛）、GTM（达人建联）、IPD（会议看板），外加需求方点名的客服培训系统。所有系统基于同一个母模板快速复制，配套的《Agent 工程化手册》让业务专家能自助开发简单 Agent。"

这句话覆盖了需求方全部四个硬要求，且每个都有可演示实物。

## Delve 指引

- M1/M2 开工前：先写 spec（需求方点名系统的具体场景要确认——达人建联的数据源是蝉妈妈导出还是手动 Excel？会议看板接飞书妙记还是贴文本？）
- M4.2 演练打分：prompt 调优是难点，先做单轮"AI 扮演客户→用户应答→AI 打分"最小闭环验证手感
- 手册复现案例选入职引导 Bot 是因为清单明确标注"RAG 脚手架直接复用，增量只有 checklist"——最快的复现证明
