## 二、宏承诺（四字段，7 条封顶）

**P1 会话完整**（会话层·最稳定）
- 承诺：需求方一次真实 session——粘 JD → 传 1–50 份 PDF → 看进度 → 队列审阅 → 改判 → 导出 CSV——端到端完成，全程不需工程知识、不看日志、不重启。
- 边界：有文本层 PDF；本地单租户。
- 失败形态：session 中任何一步需要工程词汇决策、看日志、或重启才能继续。

**P2 人工主权**（责任层·红线）
- 承诺：AI 档位仅建议；导出物中任何最终判定必须带人工确认痕迹；无全自动拒人路径。
- 边界：全部档位操作。
- 失败形态：导出 CSV 中存在 ai_verdict=reject 且 human_verdict 为空的行。

**P3 降级人话**（降级层）
- 承诺：单份失败/扫描件不阻塞整批；每类失败以一句人话 + 一句"怎么办"呈现，永不静默。
- 边界：解析、LLM、文件三类失败。
- 失败形态：整批停摆；界面出现 stack trace/技术错误码；错误无下一步指引。

**P4 数据本地**（数据层）
- 承诺：简历与结果只存本地 SQLite；除 LLM API 调用外无任何数据出机路径。
- 边界：LLM 调用的取舍见开放决策 A。
- 失败形态：代码存在 LLM API 以外的网络发送路径；数据文件出现在仓库目录外。

**P5 范围排除**（范围层）
- 承诺：v1 无对外发送、无网络抓取、无登录/多租户、无公网部署，且不为以上预埋任何代码。
- 边界：全部 v1。
- 失败形态：仓库出现"为 v2 预埋"的死路径、开关或无人调用的模块（FAILED-REVIEW 第三节的病）。

**P6 证据标准**（过程层）
- 承诺："完成"的唯一证据 = 需求方亲手完成 P1 session；自跑测试/截图/回归只算开发信号，不得出现在交付声明里。
- 边界：所有交付口径（含台账）。
- 失败形态：任何第 6 次"已修好"出现在人工验证之前。

**P7 进度诚实**（会话层·子项）
- 承诺：批处理进度与真实状态一致（n/total），完成即跳转，中途刷新进度与已出结果不丢。
- 边界：≤50 份。
- 失败形态：done>total 卡死；刷新后丢进度或丢结果。
