# VoC 数据源侦察 · 中文 UGC 平台反爬实测

> 日期：2026-10-13
> 背景：用户确认"无法直接给数据，可缓慢抓取部分"，选"换更轻的源"（B）
> 性质：可行性侦察（curl 实测各平台搜索接口的真实响应）
> 核心发现：**中文 UGC 平台已无"裸 HTTP 直接拿"的源**，JS 挑战是标配，浏览器执行不可避免

---

## 实测记录（2026-10-13，curl 单次请求）

| 平台 | 请求 | 响应 | 判定 |
|---|---|---|---|
| 小红书搜索 | 裸 curl | 301 → 跟重定向 + cookie 后 200，但 `search.feeds` **空数组** | ❌ 搜索结果不在 SSR HTML，需登录/私有 API（x-s 签名）/浏览器渲染 |
| 什么值得买搜索 | 裸 curl | 202 + probe.js **JS 挑战** | ⚠️ 需执行 JS 过挑战，登录墙强度未知 |
| 知乎搜索 | 裸 curl | 403 + zse-ck **JS 挑战** | ⚠️ 需执行 JS 过挑战 |
| B站搜索 | 裸 curl / 带代理 | **000 连接失败** | ❌ 当前网络环境到 B站不可达（直连/代理均失败） |

## 关键结论

1. **"更轻的源"的前提不成立**：原假设是"有源能裸 HTTP 拿"，实测所有候选中文 UGC 平台都有 JS 挑战或登录墙。**只要抓真实 UGC，浏览器执行 JS 挑战不可避免。**

2. **小红书的真实壁垒**：搜索结果的笔记数据（feeds）未登录状态下不返回（空数组），必须登录态或模拟客户端签名 API——这是各平台中最严格的。

3. **B站当前网络不可达**：与反爬无关，是网络层问题（代理规则可能未覆盖 B站域名）。需排查网络或放弃该源。

## 可行路径评估

| 路径 | 工程量 | 风险 | 数据贴合度 |
|---|---|---|---|
| A. 浏览器（CDP）+ 什么值得买 | 中：过 JS 挑战（可能自动过）+ 渲染搜索页 | 中：挑战强度待实测 | 中高：手游外设爆料/评测/评论 |
| B. 浏览器 + 小红书（登录） | 高：登录墙 + 滚动加载 + 限流 | 高：最强反爬 | 最高：种草/真实用户 |
| C. 浏览器 + 知乎 | 中高：过 zse-ck + 登录态 | 中高 | 中：讨论深度够但偏评测 |
| D. 电商评价（京东/天猫） | 高：登录 + 评价分页 | 高 | 最高：真实购买评价 |

## 决策建议

既然浏览器执行 JS 不可避免，**选择标准转为"浏览器里反爬最松 + 登录要求最低 + 数据最贴"**：

- **首选 A（什么值得买）**：JS 挑战可能浏览器自动过，登录墙待实测但大概率比小红书松；手游外设内容（爆料+评测+评论）质量高且聚焦消费电子
- **次选 B（小红书）**：数据最贴但成本最高，作为后续扩展源
- B站排除（网络不可达），知乎备选

**下一步**：用 CDP 浏览器实测什么值得买——JS 挑战能否自动过、未登录能否看搜索结果。这一步要真浏览器，需你确认后执行（Human Verification Gate）。
