# 飞智科技 VibeCoding 系统清单与工程加速方案

- 记录日期：2026-09-16
- 来源：会话分析两轮（①系统清单+工程量 ②工程加速方案+外部研究）
- 状态：分析稿，待用户挑选首个进入正式设计的系统

## 0. 背景：需求解读

飞智科技（消费电子品牌，"产品体验领先"战略；手游外设方向为推断，待确认），AI/IT 部由 CEO 直管。需求侧四个硬要求：

1. 熟练 Claude Code 或 Codex，有**多个 vibecoding 作品**，不要求固定开发经验
2. 交付三大标杆 Agent：招聘 / GTM 产品营销 / IPD 项目管理
3. 点名小系统：产品客服培训系统、达人自动筛选建联、自动项目看板
4. 输出《Agent 工程化手册》，让业务专家在指导下自助开发简单 Agent

**估价标尺**（vibecoding 语境成本驱动因子）：
- 数据接入：贴文本/传 Excel ≈ 0 成本 < 定时调 API < 逆向抓取（有封号/维护税）
- AI 回路：单轮生成 < 批量结构化抽取 < RAG < 多步 Agent
- 界面：单页表单+结果列表 < 看板/多视图 < 多人协作+权限
- 流程：无状态 < 有人工确认节点 < 多阶段状态机+自动催办
- 基准：熟练 Claude Code 用户，单页 CRUD + 一次 LLM 调用 ≈ 0.5–1 天

## 2. 外部研究与项目参考（2026-09-16 检索）

| 项目/研究 | 核心做法 | 实测数据 | 启示 |
|---|---|---|---|
| ChatDev（OpenBMB） | 虚拟软件公司多角色对话驱动开发 | 简单项目 $0.30、148 秒，质量分显著高于单 agent | 多 agent 分工对**质量**提升确定，对速度看任务粒度 |
| MetaGPT | SOP 编码进 prompt，按瀑布角色协作 | 与 ChatDev 互有胜负，token 消耗更高、更慢 | 角色越多≠越快，通信开销会吃掉收益 |
| UA-ChatDev（arXiv 2607.02186） | 不确定性感知路由，减少不必要讨论 | 运营成本比传统多 agent 框架降 89.09% | 多 agent 最大浪费是"agent 互相说服"，规则切断无效对话省 9 成钱 |
| Claude Code Sub-Agents 生产案例（"Feature Factory"） | 8 个专职 sub-agent：需求→架构→实现→测试→评审→安全→性能→部署 | 特性开发周期 3 周→4 天 | 并行化本质是把串行评审环节前置成并行检查 |
| Claude "Product Trinity" | PM/UX/实现 3 agent 并行问甲方 | 数周→数小时 | 需求澄清阶段三视角并行，不是产品经理一个人传话 |
| METR 2025 RCT | 经验丰富开发者+熟悉代码库+AI 工具 | 实际 +19% 耗时（主观感觉快 20%）；AI 输出约 70% 正确 | 反例：不改流程只给工具，返工吃掉收益。加速必须配验证自动化 |
| GitHub Spec Kit / AWS Kiro / BMAD | 规约驱动开发：需求→结构化 spec→计划→任务 | Spec Kit 轻量；Kiro 三文档联动；BMAD 21 角色企业级 | 需求不清时，把需求写成机器可执行 spec 比多开 agent 更减返工 |

## 3. 工程加速四方案（需求不精简，纯工程/资源视角）

- **A 多 Agent 并行流水线**：按交付物阶段切（架构/前端/后端/测试并行），orchestrator 收口。省"互相等待"。代价：协调复杂度上升、接口契约须开工前冻结、token 3–5 倍。适用：绿field、边界清晰、需求一次给齐。
- **B 模型分层路由**：最强模型只做需求澄清/架构/终审，中档做 CRUD 和单测，小模型做文档格式化。省"返工"（设计错误导致全量重写，语法错误不会）。代价：维护路由规则、强弱模型上下文传递有损耗。适用：所有项目。
- **C 并行 Agent + Git Worktree 隔离**：每 sub-agent 独立 worktree 改不同模块，review agent 合并。省"改代码冲突等待"+主 context 不被试错污染。代价：磁盘/npm 开销 ×N、合并冲突需人介入。适用：单代码库多模块、主干须随时可发布。
- **D 规约驱动开发 + 契约测试前置（SDD）**：需求先转结构化 spec（EARS+接口契约），前后端基于契约并行实现，测试先行。省"需求误解返工"（vibecoding 最大时间黑洞）。代价：前期多 0.5–1 天 spec 时间、甲方须确认 spec。适用：需求模糊、变更多、跨系统对接多。

### 代价对比（以"达人筛选建联"2–3 天基线为 1.0x）

| 方案 | 日历时间 | 人力 | Token 成本 | 返工风险 | 核心约束 |
|---|---|---|---|---|---|
| 基线：单 Agent 串行 | 2–3 天 | 1 人全程 | 1x | 中高 | 无 |
| A 多 Agent 并行 | 1–1.5 天 | 1 人+4–6 agent | 3–5x | 中 | 契约前置冻结；冲突需人仲裁 |
| B 模型分层 | 2–2.5 天 | 1 人 | 1.5–2x | 低 | 需维护路由表 |
| C Worktree 隔离 | 1.5–2 天 | 1 人+3–4 agent | 2–3x | 中低 | 环境脚本一次写对；磁盘占用大 |
| D SDD+契约前置 | 1.5–2 天（含 spec） | 1 人+BA/架构 agent | 1.2–1.5x | 最低 | 甲方确认 spec；前期看似"慢" |

Token 预算现实：Claude Code Max 20x（$200/人/月）约支撑 2–3 个重度并行 agent；17 个系统全上多 agent 需 API 按量或 Team 计划，$500–2000/人/月——给 CEO 的提案里必须写清这是"用云成本换人力时间"。

## 4. 分层应用建议

| 系统类型 | 推荐方案 | 理由 |
|---|---|---|
| 首秀 3 件（简历初筛、客服培训、达人筛选） | A + C | 快速出可演示成果；worktree 保证三 demo 并行不互相污染 |
| 标杆 Agent（IPD 评审、GTM 内容工厂） | D + B | 需求模糊会反复改，spec 前置把变更成本从改代码变成改文档；强模型只做设计评审 |
| 工具型小系统（寄样跟踪、周报、入职 Bot） | B 单 Agent + 分层 | 需求明确周期短，多 agent 协调成本 > 收益 |

## 5. 落地顺序与全局加速

- **三件首选**：达人筛选建联（营销，需求点名，Excel 即可演示）/ 简历初筛（招聘，现场扔 50 份简历出排序+理由）/ 会议→行动项看板（研发 PM，贴纪要看板自己长出来）
- **热身首选**：客服培训系统（纯 RAG 无外部依赖，半天跑通，正好做工程化手册第一个教学案例）
- **母模板复用链**：17 项中 14 项同构——`数据接入(Excel/API/贴文本) → LLM批量处理 → 人工审核队列 → 看板/报告/推送`。首个系统做成母模板（Next.js + SQLite + Claude API 封装 + 审核队列 UI + 飞书 webhook 封装），之后 fork + 换 schema + 换 prompt，工期打 6–7 折。模板本身 = 工程化手册载体
- **复用顺序**：简历初筛 → 人才库激活/面试分析 → 客服培训 → 入职 Bot → 达人筛选 → 寄样跟踪/素材库 → 会议看板 → 周报/风险雷达
- **三条红线**：外发内容（建联话术、候选人沟通）必须人工点头发送；招聘 Agent 不做全自动拒人；抓取类功能注意平台 ToS，优先用导出数据
